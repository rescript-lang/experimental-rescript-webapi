The release checklist for `@rescript/webapi` is tracked in
[#382](https://github.com/rescript-lang/experimental-rescript-webapi/issues/382). ReScript
`13.0.0-alpha.5` is the tested compiler baseline. A stable compiler is not a prerequisite;
library alpha releases may include breaking changes between versions.

## Prepare a candidate

The release version is the synchronized `version` in `package.json` and `package-lock.json`.
Use the repository's release validation before changing that version:

```shell
npm run format:check
npm run build
npm run check:features
npm test
npm run test:browser
npm run build:docs
npm run check:docs-links
npm run check:consumer
npm run check:release
```

The browser suite runs Chromium only; it is not an exhaustive browser compatibility matrix.
The consumer check compiles the packed artifact in a fresh project. A successful source build
alone is not evidence that package installation works.

The initial candidate is `1.0.0-alpha.1`, tagged `v1.0.0-alpha.1`. For each later alpha, update
`package.json` and `package-lock.json` together to the next `1.0.0-alpha.N` version, add the
user-visible changes and migration guidance to `CHANGELOG.md`, and create the matching Git tag
`v1.0.0-alpha.N` from the validated release commit. Run `npm run check:release` after the version
change; it rejects an already-published version and checks the expected alpha metadata.

## Validate and publish

The Release workflow's unprivileged `validate` job checks and packs the candidate once. It runs
`npm run check:consumer` and a publish dry-run against that exact `.tgz`; the PR and a manual
`workflow_dispatch` with `dry_run: true` use this validation path. The workflow does not expose
that runner-local archive for a later local download. If reproducing the artifact checks locally,
pack once and pass the same path to both commands:

```shell
mkdir -p .release
npm pack --json --pack-destination .release > .release/metadata.json
artifact=".release/$(node -e 'process.stdout.write(JSON.parse(require("node:fs").readFileSync(".release/metadata.json", "utf8"))[0].filename)')"
npm run check:consumer -- "$artifact"
npm publish "$artifact" --access public --tag alpha --dry-run --ignore-scripts
```

Only an authorized maintainer should start a real publication with `workflow_dispatch` from
`main` and `dry_run: false`. The separate publish job is main-only; it verifies and publishes the
validated archive with the `alpha` dist-tag and `--provenance`, and must not advance `latest`.
After a real publish, verify the registry dist-tags:

```shell
npm view @rescript/webapi dist-tags --json
```

The workflow requests npm provenance through GitHub Actions OIDC. Before the first real
publication, maintainers must configure and verify npm trusted publishing for this repository
and workflow in npm's publishing settings. The expected trusted-publisher tuple is:

- Package: `@rescript/webapi`
- Owner: `rescript-lang`
- Repository: `experimental-rescript-webapi`
- Workflow filename: `release.yml`
- GitHub environment: none

In npm's package settings, **Trusted publishing** should show those exact owner, repository, and
workflow filename fields, no GitHub environment, and allow direct `npm publish` actions.
Provenance should be enabled. These external npm account settings have not been verified from the
repository. The workflow cannot confirm them by itself.
