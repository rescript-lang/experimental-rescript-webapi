Bindings follow the browser API where that gives consumers a useful, type-safe ReScript
interface. Source files are grouped by API family, but applications use flat public owner
modules such as `WebAPI.Fetch`, `WebAPI.Request`, and `WebAPI.Element`. Internal `*Types`
modules are not application-facing namespaces.

## Method overloads

JavaScript can expose several signatures for one operation. ReScript cannot overload one value
name, so give variants distinct names that describe their input rather than appending numbers.
For example, `fetch` takes a URL and `fetchWithRequest` takes a `Request`:

```ReScript
let response = await WebAPI.Fetch.fetch("https://example.com")

let request = WebAPI.Request.fromURL("https://example.com")
let responseFromRequest = await WebAPI.Fetch.fetchWithRequest(request)
```

When several signatures differ only by optional arguments, keep a single binding with an
optional labeled argument when the browser API treats it as one operation.

## Constructor overloads

Constructors use a distinct naming convention:

- Keep singleton constructors and true default constructors named `make`.
- Name typed constructors `from*` after the source type, such as `fromString`,
  `fromArrayBuffer`, or `fromURLWithProtocols`.
- Split a hidden default constructor into `make()` plus typed `from*` constructors rather than
  leaving optional input on `make`.

For example, a `DOMMatrix` has a true default constructor alongside string and array forms:

```ReScript
let identity = WebAPI.DOMMatrix.make()
let fromTransform = WebAPI.DOMMatrix.fromString("matrix(1, 0, 0, 1, 0, 0)")
let fromComponents = WebAPI.DOMMatrix.fromArray([1., 0., 0., 1., 0., 0.])
```

Keep comments on each binding specific to the input shape and include its source type, a
consumer example, and links to the relevant MDN or ReScript type documentation. See the
[documentation guide](../07-documentation/) for the comment format.

## Dynamic browser values

Some browser properties are untagged unions in JavaScript. Model these as a small public
conversion/decoding API when consumers need to distinguish their variants; do not expose the
underlying implementation type just to make it nameable. For example, the public
`WebAPI.FillStyle` module provides conversion helpers and a decoder for Canvas fill styles.

Keep null and empty states explicit when they are part of the browser contract. Use `Null.t`
for nullable results and variants for meaningful empty values; do not replace native results
with invented defaults or unchecked casts.

## Native instance types

Model browser-owned objects as private records at both the backing declaration and every public
record view. Keep direct field reads when useful, but expose typed native setters for writable
properties instead of asking callers to mutate a private field:

```ReScript
let canvas = WebAPI.Document.createElement(document, "canvas")->WebAPI.HTMLCanvasElement.classify
switch canvas {
| Some(canvas) =>
  let width = canvas.width
  canvas->WebAPI.HTMLCanvasElement.setWidth(width + 1)
| None => ()
}
```

Use names such as `setWidth`, preserve the JavaScript property name and existing field type, and
keep throwing behavior on setters whose native operation can throw. Put shared properties on the
existing `Impl` chain so derived interfaces reuse their base setters. Do not make initializer
dictionaries, option records, callback data, or ordinary result records private merely because they
are exported beside a native interface.

For `CSSStyleDeclaration`, keep direct reads but use its existing `setProperty` operation for
individual declarations, using CSS property names such as `"background-color"` rather than the
camel-cased IDL field name. Both `float` and `cssFloat` address the `"float"` CSS property.
Replacing the complete declaration block uses `CSSStyleDeclaration.setCssText`; do not route that
operation through `setProperty`.

Private records prevent ordinary literals and record-update copies, but ReScript currently permits
a deliberate explicit structural coercion such as `ordinaryRecord :> Native.t` when a caller
recreates the full public shape. This representation is not an unforgeable native brand; do not
describe it as preventing deliberate coercions, unsafe casts, or JavaScript fabrication. A stronger
guarantee requires an opaque representation and corresponding getter APIs.
