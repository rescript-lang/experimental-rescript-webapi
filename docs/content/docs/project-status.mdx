This project is an experimental ReScript 13 alpha package, not a stable or exhaustive set of
browser bindings. It exposes a broad collection of Web API bindings, but implementation depth
varies by API and browser support is determined by the host runtime, not by whether a ReScript
module compiles.

`@rescript/webapi` alpha versions can make breaking API changes between releases. ReScript
`13.0.0-alpha.5` is the tested compiler baseline. The package peer range accepts
`>=13.0.0-alpha.5 <13.0.0`, which allows later `13.0.0` prereleases but does not claim each one
is tested; stable ReScript is not currently included in that range or required to ship this
alpha.

The install example uses the `alpha` dist-tag intended for `1.0.0-alpha.1`. At the time of this
candidate, npm's public `alpha` tag still resolves to `0.1.0-alpha-b1d58f9`; the candidate is
validated from its packed tarball, but has not been published. After an authorized publication,
the same `@alpha` install command will resolve to the new candidate.

## Contributions

[Contributions](../01-getting-started) are welcome! Please [open an issue](https://github.com/rescript-lang/experimental-rescript-webapi/issues/new/choose) if you have a specific API you would like to see added.  
This really helps prioritize our work and ensures that the most important APIs are addressed first.

## Architecture and validation

The source is organized into API-family directories, while consumers use the flat `WebAPI`
namespace and public modules such as `WebAPI.Request` and `WebAPI.Response`. Generated
implementation modules and internal type-holder modules are not part of that public surface.
Bindings are maintained and corrected by hand as well as generated; the generator is not a
reproducible source of truth for every checked-in binding.

Approximately 80 bindings still carry private-record TODOs; a blanket conversion is deferred
because the current compiler reports mutation warning 111. Generator reproducibility is also
follow-up work, not an alpha release gate.

CI uses Node 26 for ReScript compilation and Node runtime fixtures. Its Playwright suite runs
compiled Chromium regressions for the confirmed alpha contracts, including typed byte/audio
buffers, DOM constructors and narrowing, nullable Canvas/Locks results, IndexedDB deletion,
WebSocket receiver behavior, and worker Fetch. These targeted checks do not cover every binding.
There is no Firefox, WebKit, or browser-version matrix. API availability, secure-context
requirements, permissions, and user activation still depend on the browser and execution context.

## Historical backlog

Several long-standing requests remain useful references but are not individually alpha release
gates. [#236 constructor naming](https://github.com/rescript-lang/experimental-rescript-webapi/issues/236)
remains open, although a maintainer comment says it may be ready to close. The listed constructor
families now use semantic names in `FontFace`, `VideoFrame`, `MediaStream`, `Path2D`, `DOMMatrix`,
`DOMMatrixReadOnly`, `WebSocket`, and `OfflineAudioContext`. `ReadableStream.fromUnderlyingSource`
still combines an optional strategy rather than splitting it into a separately named variant.
Do not treat the issue's old checklist or comment as a recorded closure.

[#27 overload improvements](https://github.com/rescript-lang/experimental-rescript-webapi/issues/27)
also remains open. Its long checklist predates the current module layout and overlaps constructor
work in #236; numbered overloads such as `Path2D.roundRect2` and `roundRect3` still exist. This
is incremental cleanup, not an alpha gate.

[#237 module/type simplification](https://github.com/rescript-lang/experimental-rescript-webapi/issues/237)
is still open, but its implementation slices #240, #241, #242, and #243 are closed (as are #238
and #239). The current source has no root `src/*API.res` type-holder files or
`Global.window`/`Global.navigator` references. The parent checklist has not been refreshed; the
refactor appears complete in code, but its tracker remains open.

[#23 API overview](https://github.com/rescript-lang/experimental-rescript-webapi/issues/23) is a
stale point-in-time MDN coverage checklist; use the current public API documentation and source
manifest instead. [#4 error modeling](https://github.com/rescript-lang/experimental-rescript-webapi/issues/4)
remains an open design discussion: comments disagree about whether DOMException should be modeled
separately from `Error`, citing different TypeScript DOM declarations. [#5 extension helpers](https://github.com/rescript-lang/experimental-rescript-webapi/issues/5)
also remains open; comments differ on whether typed helper APIs belong in owner modules or
separate extension modules. Neither has a settled project-wide design. None of these historical
issues is automatically closed or made a blocker by this status page.

For the current release checklist and explicitly deferred work, see [#382](https://github.com/rescript-lang/experimental-rescript-webapi/issues/382).
